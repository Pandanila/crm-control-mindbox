# CRM-контроль

Веб-приложение на Python для поиска отклонений в автоматических email-рассылках Mindbox.
Учебный независимый прототип, не официальный продукт Mindbox. Все встроенные данные синтетические.

## Бизнес-проблема и решение

Гипотеза: CRM-маркетолог и CSM тратят время на ручной просмотр отчётов и могут поздно заметить прекращение отправок, снижение доставляемости или кликабельности, рост отписок.

Приложение принимает дневную статистику CSV, проверяет её, создаёт объяснимые сигналы и позволяет отметить результат проверки. Оно не устанавливает причину автоматически и не изменяет ничего в Mindbox.

## Возможности

- Обзор, очередь сигналов, графики истории и медианы.
- Загрузка CSV, автоматическое и ручное сопоставление колонок.
- Проверка дат, целых счётчиков, дубликатов и отношений между показателями.
- Четыре типа сигналов, настраиваемые пороги, контроль объёма и зрелости данных.
- Статусы «Новый», «В работе», «Проверен» и комментарии в SQLite.
- Выгрузка данных, сигналов и протокола проверок в CSV.
- Демо с четырьмя известными случаями и нормальный демонабор.

## Запуск на компьютере

Нужен Python 3.12. Команды выполняются в папке проекта.

```bash
python -m venv .venv
```

Windows:

```powershell
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m streamlit run app.py
```

macOS / Linux:

```bash
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

Откройте http://localhost:8501. Приложение сразу показывает демоданные, привязанные к текущей московской дате. Интернет не требуется для анализа после установки библиотек; внешний шрифт необязателен.

### Тесты

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Используйте Python из созданного окружения, как в командах выше. GitHub Actions выполняет те же тесты.

## Как загрузить отчёт Mindbox

1. Выберите в Mindbox отчёт по рассылкам в динамике, группировку **по дням**, автоматические email-рассылки.
2. Выгрузите детальную статистику без строк итогов. Рекомендуемый период — 35 дней.
3. Откройте «Данные», загрузите файл, проверьте сопоставление колонок и название проекта.
4. Подтвердите дневную детализацию и тип рассылок, нажмите «Проверить и загрузить».
5. В «Правилах» выберите рассылки, для которых ожидаются ежедневные отправки. Без этого проверка остановки не выполняется.
6. В «Сигналах» разберите отклонения и сохраните результаты.

Поддерживаются UTF-8, UTF-16 с BOM и Windows-1251, разделители `;`, `,`, табуляция. Лимиты: 10 МБ и 100 000 строк. Анализ одного периода — не больше 91 календарного дня.

| Поле приложения | Поле документированного экспорта Mindbox |
|---|---|
| date | ReportDate |
| campaign_id | ReportMailingId |
| campaign_name | ReportMessageName |
| sent | ReportSent |
| delivered | ReportDelivered |
| clicked | ReportClicked |
| unsubscribed | ReportUnsubscribed |
| variant — необязательно | ReportMailingVariantNum |
| brand — необязательно | ReportBrand |
| channel — необязательно | ReportChannel |
| category — необязательно | ReportCategory |

Требуются абсолютные счётчики, а не проценты и не общее число кликов по всем ссылкам. Формат даты: `YYYY-MM-DD` или `DD.MM.YYYY`. Одна строка на день, рассылку, вариант и бренд. Дубли и итоги блокируют импорт целиком, а не удаляются молча. Несколько вариантов и брендов анализируются раздельно. Если нет ID, подготовьте устойчивые уникальные ключи заранее.

Реальная клиентская выгрузка пока не предоставлена. Совместимость подтверждена на синтетическом файле с документированными названиями полей и через ручное сопоставление; конкретный файл клиента нужно проверить отдельно.

Источники: [отчёты и определения метрик](https://help.mindbox.ru/docs/mailings-dashboard), [поля экспорта](https://developers.mindbox.ru/docs/export-api-reports).

## Бизнес-правила

- Доставляемость = доставлено / отправлено × 100%.
- Кликабельность = сообщений с кликом / доставлено × 100%.
- Отписки = сообщений с отпиской / доставлено × 100%.
- База сравнения — медиана предыдущих подходящих дней в 14-дневном календарном окне, минимум 7 дней, минимум 100 сообщений для соответствующего знаменателя.
- Нет отправок: 0 у явно выбранной ежедневной рассылки при достаточной истории.
- Доставляемость: снижение от медианы минимум на 5 процентных пунктов.
- Кликабельность: относительное снижение от медианы минимум на 40%.
- Отписки: доля **больше** 1%; правило абсолютное, история не требуется.
- Текущий день не анализируется. Клики и отписки анализируются начиная с возраста 3 дней.

Пороги являются настройками учебной модели, не нормативами Mindbox. История никогда не включает текущий или будущие дни относительно проверяемого дня. Возраст данных уменьшает, но не устраняет влияние задержки реакций.

Отсутствующая строка по умолчанию означает отсутствие данных. Только явное подтверждение полноты файла разрешает считать её нулём, только для выбранных ежедневных рассылок внутри общего диапазона файла и после первого наблюдения этой рассылки. Загрузка заканчивается последним представленным днём: дни за ним не додумываются.

## Хранение и изоляция

По умолчанию данные и SQLite с результатами проверок живут в отдельной браузерной сессии. Между посетителями состояние не разделяется. При перезапуске сессии оно теряется, поэтому скачивайте результаты.

Для **локальной однопользовательской** работы можно сохранить результаты проверок в файле:

```bash
CRM_DB_PATH=runtime_data/reviews.db .venv/bin/python -m streamlit run app.py
```

Windows PowerShell:

```powershell
$env:CRM_DB_PATH="runtime_data/reviews.db"
.venv\Scripts\python -m streamlit run app.py
```

Сохраняются только ID сигналов, статусы и комментарии. Исходный CSV после перезапуска нужно загрузить снова с тем же названием проекта. Повторный анализ не создаёт новых ID для тех же сигналов и сохраняет результаты проверки. Демо и пользовательские загрузки имеют разные пространства ID. `CRM_DB_PATH` нельзя задавать для публичного многопользовательского демо: общий файл отменит изоляцию статусов.

## GitHub и бесплатная публикация

1. Создайте публичный репозиторий `crm-control-mindbox` и загрузите содержимое проекта. Не загружайте `.venv`, базы, пользовательские выгрузки и секреты.
2. На [Streamlit Community Cloud](https://share.streamlit.io/) войдите через GitHub.
3. Выберите **Create app**, репозиторий, ветку `main`, файл `app.py`.
4. В расширенных настройках выберите Python 3.12, нажмите **Deploy**.
5. Откройте выданную ссылку, проверьте оба демонабора, разделы и сохранение статуса.

Демо не требует API-ключа Mindbox. Для публикации нужен вход пользователя в сервисы. Приложение не заявляет, что развёрнуто, пока публичная ссылка не получена и не проверена.

## Ограничения

Нет авторизации, фоновых загрузок, отправки уведомлений или действий в Mindbox. Сезонность и изменения аудитории могут создавать сигналы без неисправности. Экономия времени на 30% — гипотеза, а не измеренный эффект. Не используйте публичное учебное демо как производственную систему.
