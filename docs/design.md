# Проектирование

## Сценарии
1. Открыть приложение: демонстрация шести рассылок за 35 дней, четыре отклонения за один день.
2. Загрузить файл: просмотреть строки, сопоставить поля, назвать проект, подтвердить детализацию, исправить ошибки по протоколу.
3. Проверить работу: выбрать период, настроить пороги и ежедневные рассылки, просмотреть сигналы.
4. Разобрать сигнал: проверить график, прочитать рекомендацию, открыть Mindbox самостоятельно, сохранить статус и комментарий.
5. Повторно загрузить статистику того же проекта: актуальные сигналы пересчитаны, статусы сохранены в текущей сессии или локальной SQLite.
6. Выгрузить CSV для дальнейшей работы.

## Экраны
- Обзор: 4 счётчика, приоритетные сигналы, результаты проверок, график, протокол и контроль демонабора.
- Сигналы: фильтры по типу, статусу и рассылке, таблица, карточка с графиком и форма результата.
- Данные: CSV и сопоставление, протокол ошибок, текущие строки, образец и экспорт.
- Правила: окно истории, минимальные объёмы, зрелость реакций, пороги и список ежедневных рассылок.
- О проекте: бизнес-проблема, ограничения, сценарий защиты, источники.

## Минимальная архитектура
Браузер отображает Streamlit. `app.py` вызывает чистые функции `core/` и хранит пользовательский набор в `session_state`. Данные разных посетителей не кэшируются глобально. База SQLite создаётся в памяти на сессию, только результаты проверки. Локальный путь базы можно явно включить переменной среды. Отдельный API-сервер и инфраструктура очередей не нужны.

## Данные
Дневная запись: date, campaign_id, campaign_name, sent, delivered, clicked, unsubscribed, variant, brand. Поля variant и brand необязательны. Campaign_key кодирует ID, вариант и бренд без склеивания неоднозначными разделителями. Уникальность: campaign_key + date.

Сигнал: id, project, campaign_key, date, rule, severity, value, baseline, metric, explanation, recommendation. Сигналы пересчитываются из текущего набора, старые отсутствующие сигналы не показываются как актуальные.

SQLite reviews: signal_id (PK), status, comment, updated_at. ID — хеш пространства проекта, ключа рассылки, дня и типа правила. Пересчёт не создаёт дубли. Демо и загрузки разделены. Неизменные ID позволяют сохранять результат проверки при обновлении значений. Изменившееся отклонение само по себе не переоткрывает проверенный сигнал, пользователь может изменить статус вручную.

## Алгоритмы
Только предшествующие 14 календарных дней, минимум 7 подходящих. Для доставки знаменатель sent, для кликов delivered. Абсолютный порог отписок не требует истории. Для остановки история должна содержать достаточно объёмных отправок, а ежедневность задаётся пользователем. Пропуски не входят в медиану и не считаются нулём без явного подтверждения. Проценты при нулевом знаменателе отсутствуют, не равны нулю.

Дневная группировка — обязательное подтверждение пользователя: сам файл с датами первых дней месяцев не позволяет достоверно установить гранулярность. Массовые и иные каналы блокируются, если такие значения присутствуют в сопоставленных служебных колонках.

## Тест-кейсы
Четыре контрольных отклонения; нормальный набор; пропуски с подтверждением и без; хвост остановившейся рассылки в пределах файла; малый объём; недостаточная история; поздние реакции; исключение будущего из базы; нулевой знаменатель; отрицательные и дробные счётчики; NaN/inf; будущие и неверные даты; неверный канал; дубли и разные варианты; CSV-цикл с заголовками Mindbox; формулы в CSV; сохранение статуса; изоляция сессий и проектов; постоянная локальная база; неверные настройки; текущий незавершённый день; прохождение всех экранов.
